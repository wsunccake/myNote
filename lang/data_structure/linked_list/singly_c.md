# Singly C

**singly_1.c**, **singly_2.c**, **singly_3.c** C 語言程式碼展示了三種截然不同的**鏈結串列（Linked List）設計哲學與實作方式**。以下從設計架構、優缺點及使用情境進行詳細比較：

---

### 1. 總覽比較表

| 比較維度          | singly_1.c (傳統指標傳遞)                   | singly_2.c (結構封裝實作)               | singly_3.c (侵入式鏈結串列 / Linux 風格)  |
| ----------------- | ------------------------------------------- | --------------------------------------- | ----------------------------------------- |
| **資料結構設計**  | 節點內含資料與 `next` 指標                  | 獨立出一個 `LinkedList` 結構包裝 `head` | 鏈結節點 (`list_head`) 嵌入在資料結構內部 |
| **傳參方式**      | 需使用雙重指標 (`Node **head`) 來修改頭節點 | 傳入串列物件指標 (`LinkedList *ll`)     | 傳入內嵌的 `List_Head *`                  |
| **封裝性**        | 低（直接暴露節點指標給外部操作）            | 中（將 `head` 封裝在 `LinkedList` 內）  | 高（鏈結邏輯與資料完全解耦）              |
| **通用性/複用性** | 低（專屬於特定型別的 `Node`）               | 低（專屬於特定型別的 `Node`）           | **極高**（同一套串列邏輯可串接任何結構）  |
| **程式碼複雜度**  | 簡單直觀                                    | 簡單直觀                                | 複雜（涉及指標算術與型別強轉）            |

---

### 2. 各實作詳細解析

#### singly_1.c：傳統單向鏈結串列 (Pointer-to-Pointer)

- **特點**：使用純粹的 `Node` 串接。當函式需要改變鏈結串列的頭部（例如 `append` 到空串列或 `pop` 刪除節點）時，必須傳入指向頭指標的指標（即 **`Node **head`\*\*）。
- **優點**：
- 沒有多餘的包裝結構，最貼近教科書的基礎教學。

- **缺點**：
- 介面不夠直覺（到處都是 `**`），呼叫端容易寫錯。
- 缺乏物件導向或封裝的概念，狀態管理分散。

#### singly_2.c：結構封裝式鏈結串列 (Wrapper Struct)

引入了一個 `LinkedList` 結構體來管理 `head` 指標：

```c
typedef struct {
    Node *head;
} LinkedList;

```

- **特點**：將鏈結串列的「控制權/狀態」與「節點資料」分離。函式只需傳入 `LinkedList *ll`。
- **優點**：
- **API 更乾淨**：避免了 `singly_1.c` 中醜陋且容易混淆的雙重指標（`Node **`）。
- 程式碼架構更清晰，具備初步的物件導向封裝雛形。

- **缺點**：
- 仍然綁死在特定的 `Node` 結構上（`data` 只能是 `int`），無法輕易複用到其他資料型別。

#### singly_3.c：侵入式鏈結串列 (Intrusive Linked List / Linux Kernel Style)

模仿 **Linux 核心（Linux Kernel）** 中著名的 `list_head` 設計：

```c
struct list_head {
    struct list_head *next;
};
struct node {
    int data;
    List_Head list; // 將鏈結節點「嵌入」資料結構內
};

```

- **特點**：鏈結串列不包含資料，反而是資料結構內部包含了鏈結節點。透過指標算術（程式碼中的 `t - 1` 或 Linux 的 `container_of` 巨集）從內部的 `List_Head` 反推回整個 `Node` 的記憶體位址。
- **優點**：
- **極高的複用性**：這套 `List_Head` 邏輯可以拿去串接任何結構（只要把 `List_Head` 放進去），不需要為每個新型別重寫 `append` 或 `traverse`。

- **缺點**：
- **可讀性與安全性低**：需要透過指標減法來取得外層結構的資料，如果型別對齊或指標計算出錯，會導致嚴重的記憶體錯誤（Segmentation Fault）。

---

## singly_2.c vs singly_3.c

表面上看起來，**singly_2.c** 和 **singly_3.c** 確實都有一個共同點：**它們都打破了傳統單純用一個 `Node *head` 走天下的做法，引入了額外的結構來協助管理鏈結**。

但如果深入看它們的**記憶體佈局與設計哲學**，這兩者其實是**完全截然不同**的思維：

### 1. 核心差異比較表

| 比較維度               | singly_2.c (容器包裹法 / Wrapper)                                     | singly_3.c (侵入式鏈結 / Intrusive List)                             |
| ---------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **誰指著誰？**         | 外部的 `LinkedList` 指向 **整個 `Node**`。                            | 鏈結指標 (`List_Head`) 嵌在 **`Node` 內部**。                        |
| **指標的型別**         | `Node *` (指向包含資料的完整節點)                                     | `List_Head *` (只指向另一個 `List_Head`)                             |
| **通用性**             | **低**。這個 `LinkedList` 只能用來串接包含 `int data` 的特定 `Node`。 | **極高**。`List_Head` 毫不在乎外面包了什麼資料，它可以串接任何結構。 |
| **資料與鏈結的耦合度** | 耦合（資料與 `next` 指標綁在同一個 `Node` 裡）。                      | 解耦（鏈結邏輯和資料本身分開，透過指標算術結合）。                   |

### 2. 深入剖析：兩者的本質差別

#### **singly_2.c 的邏輯：管理者與物品**

在 singly_2.c 中，`LinkedList` 就像是一個「倉庫管理員」，手上拿著一個本子記錄著第一個箱子（`Node`）在哪裡：

- `LinkedList` 是一個獨立的外部容器。
- 箱子 (`Node`) 裡面裝著資料 (`int data`) 和下一個箱子的地址 (`next`)。
- **特點**：邏輯很直覺，就像一般物件導向語言（如 Java/Python）的寫法。

#### **singly_3.c 的邏輯：零件與積木（Linux 核心精神）**

在 singly_3.c 中，`List_Head` 就像是一個「標準化的扣環」，直接黏在每個物件身上：

- 串列本身只是一串扣環（`List_Head *list`），它**完全不知道外面包的是什麼資料**（不知道有 `int data`、也不知道是 `Node` 還是其他結構）。
- 當它想拿到外面的資料時，必須透過程式碼中的指標減法（也就是程式碼裡的 `t - 1` 或 Linux 著名的 `container_of` 巨集），「從零件反推回整台機器」的記憶體位置。
- **特點**：這就是為什麼 Linux 核心能用同一套 `list_add` 函數去串接行程（Process）、檔案（File）、網路封包（Sk_buff）等完全不同的核心結構。

### 程式碼片段

#### 1. 結構定義的差異 (Struct Definition)

- **singly_2.c (外包容器法)**：
  `LinkedList` 是一個獨立的「管理者」，它抓著整個 `Node` 的指標；而 `Node` 裡面同時包含了資料與下一個節點的指標。

```c
// singly_2.c 的結構
typedef struct {
    Node *head;  // 外部容器，直接指向完整的 Node
} LinkedList;

struct node {
    int data;
    struct node *next; // 資料與鏈結綁死在同一個結構裡
};

```

- **singly_3.c (侵入式設計)**：
  串列本身只是一條純粹的鏈結（`List_Head`），它被「塞進」了 `Node` 裡面。鏈結本身完全不知道外面包了什麼資料。

```c
// singly_3.c 的結構
struct list_head {
    struct list_head *next; // 純粹的指標，不知道有 data 這件事
};

struct node {
    int data;
    List_Head list; // 鏈結被「嵌入」在資料結構內部
};

```

#### 2. 資料存取方式的差異（核心的程式碼表現）

- **singly_2.c：直覺的指標存取**
  因為指標直接指向 `Node`，所以只要拿著指標就能直接點出 `data`：

```c
// singly_2.c 中的 traverse 函數
while (head != NULL)
{
    printf("%d ->", head->data); // 直接透過 head->data 取得資料
    head = head->next;
}

```

- **singly_3.c：指標算術與反推 (Pointer Arithmetic)**
  在 singly_3.c 中，你走訪時拿到的其實是內部的小零件 `List_Head`。為了印出或取得外面的 `data`，它必須使用指標減法（如 `t - 1`）去把外面的大結構位置「算」回來：

```c
// 3.c 中的 ex() 函數片段
printf("*(list->next - 1): %d\n", *(list->next - 1));
// ↑ 這裡的 list->next 是 List_Head*，減 1 是為了往前推，試圖抓到外層 node 的資料

// 以及 container_of 函數
List_Head *container_of(int n, List_Head *l)
{
    // ... 略 ...
    printf("container: %d\n", *(t - 1));
    return t - 1; // 從內部零件位址，反推回整體的記憶體位址
}

```

- **singly_2.c**，程式碼都是在跟**完整的節點 (`Node`)** 打交道。
- **singly_3.c**，程式碼則是不斷在跟**內嵌的零件 (`List_Head`)** 打交道，並透過數學運算（減法）去偷看隔壁的資料。
- **singly_2.c** 像是「專用容器」：為了解決指標傳遞的麻煩，用一個結構把 `head` 包起來，但專屬於特定資料型別。
- **singly_3.c** 像是「通用萬能插座」：把鏈結邏輯縮小成純粹的指標遊戲，透過巧妙的記憶體位址計算，達到程式碼最大複用性。

注意 singly_3.c 裡面這種 `*(t - 1)` 的寫法，如果結構裡面欄位順序或型別稍微改動，就很容易算錯位置引發當機嗎？

---

### 總結

- 如果是**簡單的練習或小型專案**，**`singly_2.c`** 的封裝方式寫起來最自然且易於維護。
- 如果是在寫**底層系統程式（如作業系統核心）**追求極致的效能與通用性，**`singly_3.c**` 的侵入式設計則是標準解答。
