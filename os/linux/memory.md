# Linux Memory 診斷備忘

## free

free 指令是查看「當前即時」記憶體使用量最快、最常用的工具。

```bash
linux:~$ free -h
               total        used        free      shared  buff/cache   available
Mem:            46Gi       1.8Gi        22Gi       1.4Mi        22Gi        44Gi
Swap:          8.0Gi          0B       8.0Gi
```

- **total**：
  - 總實體記憶體大小。
- **used**：
  - 已被行程使用的記憶體。
  - 其計算公式為：total - free - buffers - cache。
- **free**：
  - 完全未被使用的空閒記憶體。
  - ⚠️ 注意：Linux 的記憶體管理策略是「不用白不用」，會把空閒記憶體盡可能拿來當快取。
  - 因此這個數值通常很低，但並不代表記憶體不夠用！shared：多個行程共享的記憶體空間（主要是 tmpfs 虛擬檔案系統）。
- **buff/cache**：
  - 磁碟暫存與快取（Buffers/Cache）。
  - 核心用來加速硬碟讀寫的快取空間。
  - 當應用程式需要記憶體時，這部分空間會立刻被釋放出來。
- **available**：
  - 💡 最重要的指標！系統真正「可用」的剩餘記憶體。
  - 估算在不使用 Swap（交換空間）的前提下，還能啟動多少新程式。

## vmstat

vmstat（Virtual Memory Statistics）指令是分析虛擬記憶體、行程（Processes）以及 CPU 完整活動狀態的利器。

```bash
linux:~$ vmstat -S M
procs -----------memory---------- ---swap-- -----io---- -system-- -------cpu-------
 r  b   swpd   free   buff  cache   si   so    bi    bo   in   cs us sy id wa st gu
 1  0      0  23345      4  22564    0    0    22   336  386    0  0  0 99  0  0  0
```

📊 memory 區塊（記憶體狀態）

- **swpd**：
  - 已使用的虛擬記憶體（Swap）總量。
  - 如果這個值很大，代表實體記憶體曾經不夠用，部分資料被移到了硬碟。
- **free**：
  - 完全空閒的實體記憶體（RAM）。
  - 與 free 指令的 free 欄位相同，通常會被 Linux 拿去當快取，因此數字偏小是正常的。
- **buff**：
  - 核心用來作為磁碟區塊暫存（Buffer）的記憶體量。
- **cache**：
  - 核心用來作為檔案頁面快取（Page Cache）的記憶體量（通常這個欄位最大）。

🔄 swap 區塊（💡 判斷記憶體瓶頸的核心指標）

- **si** (Swap-in)：
  - 每秒從硬碟（Swap）置換回實體記憶體的資料量。
- **so** (Swap-out)：
  - 每秒從實體記憶體移出、寫入硬碟（Swap）的資料量。

## sar

sar（System Activity Reporter）指令是分析記憶體使用量與歷史趨勢最強大的工具之一。

```bash
linux:~$ sar -r
Linux 7.0.0-14-generic (linux)      09/22/2026      _x86_64_        (4 CPU)

01:00:05 AM kbmemfree   kbavail kbmemused  %memused kbbuffers  kbcached  kbcommit   %commit  kbactive   kbinact   kbdirty
01:10:05 AM  37610032  46725180    698472      1.45      4784   9273628   2110456      3.72    490120   9120876       592
01:20:05 AM  37598232  46713784    709860      1.47      4784   9274040   2117924      3.74    497772   9120932       764
01:30:05 AM  30526128  46479412    940392      1.95      4784  16105556   2206120      3.89    752556  15952436     37272
01:40:05 AM  23902812  46413040   1002484      2.08      4784  22647144   2377788      4.20    768652  22493648       588
Average:     35530626  46669130    753370      1.56      4784  11294211   2147477      3.79    543453  11141309      4305
```

1. 容量與使用總量（基礎指標）

- **kbmemfree**：
  - Kilobytes Memory Free
  - 剩餘的實體記憶體（單位：KB）。
  - 完全未被系統使用的空閒記憶體。
  - ⚠️ Linux 預設會把空閒記憶體盡可能拿去當快取，因此此數值極低是常態，不代表記憶體不足。
- **kbavail**
  - Kilobytes Available
  - 💡 最重要的可用指標。估算在不觸發 Swap 的前提下，系統真正還能拿來啟動新程式的記憶體總量。
  - 看這個最準！ 它是將 kbmemfree 加上可回收的快取綜合計算而得。此欄位充裕就代表記憶體絕對夠用。
- **kbmemused**：
  - Kilobytes Memory Used
  - 已使用的實體記憶體（單位：KB）。
  - 在較新的 Linux 核心中，這個數值包含了「程式真正佔用」加上「暫存與快取（Buffers/Cache）」。
- **%memused**：
  - Percent Memory Used
  - 實體記憶體使用率百分比。計算公式：kbmemused / 總實體記憶體。
  - ⚠️ 注意：因為 Linux 預設會將空閒記憶體拿來做快取，所以此欄位長期接近 90%+ 是正常現象，不代表記憶體真的不夠用。若要看真正的瓶頸，必須改看 %commit。

2. 快取與緩衝機制（效能加速指標）

- **kbbuffers**：
  - Kilobytes Buffers
  - 核心用來作為磁碟原始區塊（Raw Block）暫存的記憶體量。
  - 主要用於存放磁碟的中繼資料（Metadata），如檔案目錄、權限等結構資訊，通常佔用量較小。
- **kbcached**：
  - Kilobytes Cached
  - 核心用來作為檔案頁面快取（Page Cache）的記憶體量。
  - 系統讀取過的檔案（如網頁、日誌、資料庫文件）會暫存在這。當新程式需要空間時，這塊區域會被立刻釋放。

3. 承諾與風險評估（系統崩潰預警指標）

- **kbcommit**：
  - Kilobytes Committed
  - 保證當前系統所有工作能安全運行所需的記憶體總量（RAM + Swap 總需求估算）。
  - 這是行程（Processes）向系統申請並被核准的記憶體總和，代表「若所有程式同時要把空間塞滿，最極端需要多少 RAM」。
- **%commit**：
  - Percent Committed
  - 承諾記憶體佔系統總空間（RAM+Swap）的百分比
  - 💡 伺服器穩定度指標：• < 100%：絕對安全。• > 100%：代表「超額承諾（Overcommit）」。如果程式此時真的同時把記憶體塞滿，系統就會觸發 OOM Killer 強制隨機殺掉行程以防當機。

4. 核心底層活躍度（資源回收優先序指標）

- **kbactive**：
  - Kilobytes Active
  - 活躍記憶體。最近被頻繁讀寫、存取的記憶體頁面（Pages）。
  - 核心絕對不會優先回收這塊區域，因為裡面的資料正在被頻繁使用，回收會嚴重拖慢程式速度。
- **kbinact**：
  - Kilobytes Inactive
  - 雖然被佔用，但已經「很久沒有被程式存取」的記憶體頁面。
  - 資源回收的首要目標！ 這裡面多半是之前讀過、但現在擺著沒用的舊快取。系統只要記憶體一吃緊，會秒速清空這塊空間，完全不影響效能。
- **kbdirty**：
  - Kilobytes Dirty
  - 髒頁記憶體（Dirty Pages）。已在記憶體中被修改，但尚未真正寫入硬碟的暫存資料。
  - 數值飆高代表有密集寫入（如產生大檔案、資料庫存檔）。💡 常態下應該要「迅速飆高後又降回接近 0」，如果持續數分鐘居高不下，代表硬碟寫入速度太慢（I/O 瓶頸）。


💡 一分鐘快速診斷

1. 先看 kbavail：只要它很大，伺服器就高枕無憂。
2. 再看 %commit：如果超過 100%，就要開始清查是哪個行程申請了太多記憶體。
3. 如果遇到系統卡頓，看 kbdirty：若它卡在高點降不下來，說明硬碟寫入遇到瓶頸，不是記憶體不夠，而是硬碟太慢！

## 🔍 判斷記憶體是否真的不足

**free**

1. 記憶體充足 available 還有很多空間。系統運行順暢，有足夠的快取加速讀寫。
2. 記憶體吃緊 available 接近 0，且 Swap -> used（已用交換空間）開始不斷飆高。

**vmstat**

1. 健康狀態：si 和 so 長期為 0。這代表即便 free 欄位很小，但實體記憶體完全夠用，不需要跟硬碟頻繁交換資料。
2. 記憶體瓶頸（發生 Thrashing 異常）：如果 si 和 so 持續大於 0（例如幾十或幾百 MB/s），代表實體記憶體已經嚴重不足，系統正陷入「不斷把記憶體寫入硬碟、又從硬碟讀回記憶體」的惡性循環，這會導致伺服器 I/O 飆高、極度卡頓。

**sar**

1. 觀察 kbmemfree + kbbuffers + kbcached： 這是系統真正「可用」的記憶體空間。如果三者加起來非常低，且 kbcommit 居高不下，才代表記憶體吃緊。
2. 交叉檢查 Swap 狀態（sar -S）： 如果發現 kbswpused（已用 Swap）持續增加，且 sar -W 顯示有頻繁的 pswpin/s 和 pswpout/s（換入/換出），代表實體記憶體真的不夠，系統被迫不斷讀寫硬碟，這會導致伺服器 I/O 嚴重卡頓。

## 🛠 設計目的、資料來源和適用場景

- **free**
  - 定位: 即時狀態快照
  - 時間軸: 僅看當下（或簡短的連續即時更新）
  - 優點: 語法最簡單，欄位最直覺，能一眼看出核心指標 available（可用記憶體）。
  - 缺點: 無法查看過去歷史紀錄，看不到記憶體交換（Swap）的進出速度。

- **vmstat**
  - 定位: 動態趨勢與系統壓力分析
  - 時間軸: 即時連續監控（如每秒更新）
  - 優點: 能將記憶體與 Swap 進出流量（si/so）、CPU、I/O 綜合對比，極適合排查即時卡頓。
  - 缺點: 輸出的表格欄位較多，初學者不易快速閱讀，單位固定（舊版）或調整較不便。

- **sar**
  - 定位: 歷史紀錄與長期趨勢分析
  - 時間軸: 當天或過去特定日期的歷史紀錄
  - 優點: 全能型工具。可以調閱過去（如昨天、上週）系統變慢時的記憶體數據，用來事後驗屍（Post-mortem）。
  - 缺點: 需要系統預先安裝並啟動 sysstat 服務來背景收集資料，預設單位（KB）較難閱讀。

- 記憶體判斷
  - free 最棒：直接提供 available 欄位，這是一個由 Linux 核心估算、扣除不可釋放快取後的「真正可用空間」。
  - sar 與 vmstat：只提供 free（完全空閒）、buff、cache。你必須自己把這三個欄位加總，才能估算出大概的可用量。

- Swap（交換空間）深度
  - free 只能看容量： Swap 總共用掉多少、剩多少。
  - sar -W 可以看速度：顯示每秒換入/換出的頁數（pswpin/s）。
  - vmstat 最直覺：直接在主畫面顯示 si (Swap-in) 與 so (Swap-out) 的資料量速度（如每秒多少 MB），能立刻判斷系統是否因記憶體不足而卡死在硬碟 I/O。
