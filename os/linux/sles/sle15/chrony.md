# chrony

## history

網路時間協定（NTP）的演進歷程反映了電腦對時間精確度的需求不斷提升，以及網路環境的變化。從早期的簡化版本到功能強大的現代實作，這段歷史可以分為三個主要階段：

1.  `NTP` (Network Time Protocol)：精準時間同步的基石

    NTP 是由美國特拉華大學的 David L. Mills 博士在 1980 年代初期開發的，旨在解決網路中電腦時間同步的問題。NTP 的設計非常複雜且強大，它不僅僅是簡單地將伺服器時間傳給客戶端，還包含了一套複雜的演算法來精確計算並補償網路延遲、抖動以及時鐘漂移。

    NTP 的核心特色包括：

         - 分層架構（Stratum）：NTP 伺服器被分為不同的層級，Stratum 0 是最精確的參考時鐘（如原子鐘或 GPS 時鐘），Stratum 1 伺服器直接與 Stratum 0 連接，依此類推。客戶端通常會連接到 Stratum 1、2 或 3 的伺服器。
         - 多伺服器冗餘：一個 NTP 客戶端可以同時向多個伺服器請求時間，並透過複雜的統計演算法來篩選出最可靠、最精確的時間來源，有效防止單一伺服器故障或惡意篡改。
         - 持續調整時鐘頻率（Clock Discipline）：NTP 不會粗暴地「跳躍」時間（除非時間差異過大），而是透過微調系統時鐘的頻率來緩慢修正時間偏差，確保時間平穩過渡，避免對應用程式造成不良影響。

    NTP 的強大功能使其成為企業、研究機構和網際網路基礎設施中不可或缺的標準，至今仍是絕大多數網路時間同步的基礎。

2.  `SNTP` (Simple Network Time Protocol)：輕量級的替代方案

    儘管 NTP 效能強大，但它的複雜性對於一些資源有限的設備（如嵌入式系統、網路路由器）來說是個負擔。為此，SNTP 在 1990 年代初期被提出。

    SNTP 就像其名稱所暗示的，是 NTP 的簡化版。它使用的協定封包格式與 NTP 完全相同，因此可以與 NTP 伺服器互通，但其客戶端的運算邏輯被大幅簡化。

        - 單伺服器運作：SNTP 客戶端通常只會與一個時間伺服器進行同步，不具備 NTP 多伺服器篩選和冗餘的能力。
        - 缺乏漂移補償：SNTP 通常只會簡單地將時間伺服器的時間設定到本機，而不會持續地微調時鐘頻率來補償時鐘漂移。這可能導致客戶端在兩次同步之間的時間精準度較差。

    由於這些簡化，SNTP 的精確度和可靠性遠不及 NTP。因此，官方建議只在同步準確度要求不高，且客戶端位於同步網路最末端的情況下使用 SNTP。

3.  `Chrony`：針對現代網路和虛擬化環境的新世代方案

    Chrony 是一個相對較新的 NTP 軟體實作，旨在解決傳統 NTP 軟體（例如 ntpd）在現代網路環境中遇到的挑戰。Chrony 在設計上從頭開始，以提供更高的精確度和在不穩定環境下的更佳表現。

    Chrony 的優勢包括：

        - 更快的同步速度：Chrony 能在更短的時間內將系統時鐘同步到正確的時間，這對於經常開關機的筆記型電腦或虛擬機器非常有用。
        - 更好的不穩定網路支援：它能更好地應對網路連線不穩定、頻繁中斷或延遲抖動嚴重的環境，例如透過行動網路連接的設備。
        - 針對虛擬化環境優化：Chrony 能夠更有效地處理虛擬機器中常見的時鐘漂移問題，並使用更先進的演算法來維持準確性。
        - 更低的資源消耗：相較於傳統的 ntpd，Chrony 更加輕量，佔用更少的 CPU 和記憶體資源。

    由於這些優點，許多現代 Linux 發行版（如 Red Hat Enterprise Linux、SUSE）已將 Chrony 作為預設的時間同步服務，取代了傳統的 ntpd。

| 服務   | 誕生時間 | 主要特點                             | 適用場景                     |
| ------ | -------- | ------------------------------------ | ---------------------------- |
| NTP    | 1980s    | 複雜演算法、多伺服器冗餘、高精確度   | 伺服器、企業網路核心設備     |
| SNTP   | 1990s    | 簡化版、單伺服器、低運算量           | 嵌入式設備、簡單的網路設備   |
| Chrony | 2000s    | 快速同步、輕量級、針對不穩定網路優化 | 伺服器、筆記型電腦、虛擬機器 |

## service

```bash
sle:~ # systemctl enable chronyd
sle:~ # systemctl start chronyd
```

## config

```bash
sle:~ # vi /etc/chrony.conf
sle:~ # ls /etc/chrony.d
```

## command

```bash
sle:~ # chronyc sources         # list ntp source
sle:~ # chronyc sources -v
sle:~ # chronyc sourcestats
sle:~ # chronyc tracking
sle:~ # chronyc activity

sle:~ # chronyc -a makestep
sle:~ # chronyc -a 'burst 4/4'       # sync time
```
