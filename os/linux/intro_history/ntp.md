# ntp

Simple Network Time Protocol)：輕量級的替代方案

    儘管 NTP 效能強大，但它的複雜性對於一些資源有限的設備（如嵌入式系統、網路路由器）來說是個負擔。為此，SNTP 在 1990 年代初期被提出。

    SNTP 就像其名稱所暗示的，是 NTP 的簡化版。它使用的協定封包格式與 NTP 完全相同，因此可以與 NTP 伺服器互通，但其客戶端的運算邏輯被大幅簡化。

        - 單伺服器運作：SNTP 客戶端通常只會與一個時間伺服器進行同步，不具備 NTP 多伺服器篩選和冗餘的能力。
        - 缺乏漂移補償：SNTP 通常只會簡單地將時間伺服器的時間設定到本機，而不會持續地微調時鐘頻率來補償時鐘漂移。這可能導致客戶端在兩次同步之間的時間精準度較差。

    由於這些簡化，SNTP 的精確度和可靠性遠不及 NTP。因此，官方建議只在同步準確度要求不高，且客戶端位於同步網路最末端的情況下使用 SNTP。

3.  `Chrony`：針對現代網路和虛擬化環境的新世代方案

    Chrony 是一個相對較新的 NTP 軟體實作，旨在解決傳統 NTP 軟體（例如 ntpd）在現代網路環境中遇到的挑戰。Chrony 在設計上從頭開始，以提供更高的精確度和在不穩定環境下的更佳表現。

    Chrony 的優勢包括：

        - 更快的同步速度：Chrony 能在更短的時間內將系統時鐘同步到正確的時間，這對於經常開關機的筆記型電腦或虛擬機器非常有用。
        - 更好的不穩定網路支援：它能更好地應對網路連線不穩定、頻繁中斷或延遲抖動嚴重的環境，例如透過行動網路連接的設備。
        - 針對虛擬化環境優化：Chrony 能夠更有效地處理虛擬機器中常見的時鐘漂移問題，並使用更先進的演算法來維持準確性。
        - 更低的資源消耗：相較於傳統的 ntpd，Chrony 更加輕量，佔用更少的 CPU 和記憶體資源。

    由於這些優點，許多現代 Linux 發行版（如 Red Hat Enterprise Linux、SUSE）已將 Chrony 作為預設的時間同步服務，取代了傳統的 ntpd。

| 服務   | 誕生時間 | 主要特點                             | 適用場景                     |
| ------ | -------- | ------------------------------------ | ---------------------------- |
| NTP    | 1980s    | 複雜演算法、多伺服器冗餘、高精確度   | 伺服器、企業網路核心設備     |
| SNTP   | 1990s    | 簡化版、單伺服器、低運算量           | 嵌入式設備、簡單的網路設備   |
| Chrony | 2000s    | 快速同步、輕量級、針對不穩定網路優化 | 伺服器、筆記型電腦、虛擬機器 |
