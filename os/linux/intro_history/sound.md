# sound

## history

Linux 系統的音效架構經歷了長期的演變，從最初的簡單模式，逐步發展為能處理複雜多媒體需求的現代系統。這個演進過程中，主要的聲音伺服器可以依時間順序分為幾個階段：

1. OSS (Open Sound System)

   - 時間：1990 年代 - 2000 年代初期
   - 詳細介紹：
     OSS 是 Linux 早期最主要的音效架構，它直接在核心層面提供應用程式與音效硬體的介面。它的設計概念相對簡單，將音效卡視為一個檔案，應用程式可以透過讀寫 /dev/dsp 等裝置檔案來播放和錄製聲音。
   - 優點：
     - 簡單直接： 核心層的設計使得它的延遲非常低。
     - 歷史悠久： 在早期 Linux 系統上廣泛使用，許多老舊的應用程式都是基於 OSS 開發。
   - 缺點：
     - 單一存取： 一個時間點只能有一個應用程式佔用音效裝置，這意味著當你在聽音樂時，無法同時播放其他程式的音效，例如系統通知音。
     - 缺乏混音功能： 無法將多個音源混合在一起。
     - 不支援網路音訊： 沒有內建的網路串流功能。

2. ALSA (Advanced Linux Sound Architecture)

   - 時間：1990 年代末期 - 至今
   - 詳細介紹：
     ALSA 最初是一個獨立的專案，旨在取代 OSS 的核心音效驅動。它提供了更現代、功能更強大的核心音訊驅動程式，並在 2.6.x 版本的 Linux 核心中被正式納入。ALSA 提供了硬體抽象層，讓應用程式無需直接與硬體溝通。雖然 ALSA 解決了多應用程式存取的問題（透過 Dmix 外掛），但它本身仍然是核心層面的架構，缺乏使用者空間的混音和高階功能。
   - 優點：
     - 多重存取： 透過 Dmix 等外掛，可以讓多個應用程式同時播放聲音。
     - 模組化設計： 驅動程式與核心分開，易於維護和更新。
     - 低延遲： 核心層的設計使其延遲仍然很低，特別是直接使用時。
   - 缺點：
     - 缺乏高階功能： ALSA 本身沒有內建網路音訊、音量控制、音訊路由等桌面所需的功能，需要搭配其他伺服器才能實現。

3. JACK (JACK Audio Connection Kit)

   - 時間：2001 年 - 至今
   - 詳細介紹：
     JACK 是一個專為專業音訊應用而設計的聲音伺服器。它的核心目標是提供極低的延遲和精確的同步功能，這對於音樂家、錄音工程師和廣播製作人員至關重要。JACK 允許使用者將不同應用程式的音訊流像插線一樣連接起來，創建複雜的音訊工作流。
   - 優點：
     - 極低延遲： 能夠實現毫秒級甚至亞毫秒級的延遲，這對於即時音訊處理至關重要。
     - 強大路由功能： 允許使用者自由地路由任何音訊輸入到任何輸出，或應用程式之間。
     - 專業級應用： 是 Linux 上許多專業 DAW（數位音訊工作站）和音訊軟體的首選。
   - 缺點：
     - 不適合一般桌面使用： 它的配置和使用比較複雜，對於一般使用者來說過於繁瑣。
     - 相容性問題： 許多非專業的桌面應用程式不支援 JACK。

4. PulseAudio

   - 時間：2004 年 - 至今
   - 詳細介紹：
     PulseAudio 是一個在 ALSA 之上運行的聲音伺服器，它旨在解決 ALSA 在使用者空間功能上的不足。PulseAudio 提供了豐富的桌面音訊功能，如網路音訊串流、多個應用程式的自動混音、細緻的音量控制、裝置切換等，使其成為 Linux 桌面環境的實際標準。
   - 優點：
     - 豐富的桌面功能： 解決了 ALSA 缺乏的許多日常功能，大幅提升了使用者體驗。
     - 易於使用： 大多數情況下，它會自動工作，無需使用者手動配置。
     - 網路音訊： 允許將音訊串流到其他電腦。
   - 缺點：
     - 延遲較高： 由於其架構，延遲比 ALSA 或 JACK 要高，不適合專業音訊。
     - 偶爾出現小問題： 在某些情況下，可能會有驅動衝突或配置問題。

5. PipeWire

   - 時間：2017 年 - 至今
   - 詳細介紹：
     PipeWire 是一個全新的、現代化的聲音伺服器，旨在解決 PulseAudio 和 JACK 的不足，並將它們的功能融合到一個單一的框架中。它的核心目標是成為 Linux 上所有多媒體串流的通用解決方案，無論是音訊還是視訊。它能同時處理低延遲的專業音訊（如 JACK）和高相容性的桌面音訊（如 PulseAudio），並支援視訊串流，使其成為螢幕分享、視訊會議等應用的理想選擇。
   - 優點：
     - 極低延遲： 能夠同時滿足專業音訊和桌面應用。
     - 一體化架構： 統一處理音訊和視訊，簡化了多媒體子系統。
     - 更好的安全性： 提供更細緻的權限控制。
     - 相容性： 向後相容 PulseAudio 和 JACK 應用程式，使過渡更平順。
   - 缺點：
     - 相對新穎： 雖然發展迅速，但相較於 PulseAudio，其穩定性和相容性仍在持續改進中。

總結演進
Linux 的音效演變可看作是從 核心驅動 (OSS, ALSA) 發展到 使用者空間伺服器 (PulseAudio, JACK)，最終走向 整合式多媒體框架 (PipeWire) 的過程。這個演進解決了早期架構的單一存取、高延遲等問題，並最終實現了現代桌面與專業音訊的無縫整合。
