# su sudo

⚙️ `su` (Switch User) 介紹

`su` 指令允許您切換到另一個用戶帳號，並以該用戶的身份執行操作。

**功能與用法**

- 用途：最常見的用法是從普通用戶切換到 root 用戶，以執行需要更高權限的系統管理任務。
- 語法：
  - su：切換到 root 用戶（需要輸入 root 密碼）。
  - su - 或 su -l：切換到 root 用戶，同時載入 root 的環境變數（這是推薦的用法，確保環境設定正確）。
  - su <user_name>：切換到指定的用戶（需要輸入該用戶的密碼）。
- 密碼：切換到 root 需要 root 密碼；切換到其他用戶需要該用戶的密碼。
- 會話：切換後，您將在新的 shell 會話中，直到輸入 exit 返回原來的用戶會話。

**優點 (Advantage)**

- 完整權限：一旦切換到 root，您就擁有系統的所有權限，可執行任何管理任務。
- 環境切換：su - 可以完整地切換到目標用戶的環境，確保工作正確性。

**缺點 (Disadvantage)**

- 安全性風險：
  - 要求知道 root 密碼，這增加了密碼洩露的風險。
  - 一旦以 root 身份登入，用戶可能會在不知情的情況下執行破壞性的指令，風險極高。
- 可追蹤性差：多個管理員共用同一個 root 密碼時，很難追蹤哪個管理員執行了特定的操作。
- 長時間高權限：用戶通常會在完成任務後忘記 exit，長時間保持在 root 狀態。

🛡️ `sudo` (Substitute User Do) 介紹

`sudo` 指令允許授權的普通用戶以另一個用戶（預設為 root）的身份執行單個指令。

**功能與用法**

- 用途：以受控的方式授予普通用戶執行特定管理任務的權限，無需知道 root 密碼。
- 語法：sudo <command>（例如：sudo apt update）。
- 密碼：
  - 需要輸入自己的用戶密碼（而不是 root 密碼）。
  - 密碼驗證成功後，在一段預設時間內（通常是 5 分鐘），用戶可以繼續使用 sudo 而無需再次輸入密碼。
- 授權：用戶必須在 /etc/sudoers 檔案中被授權才能使用 sudo。通常，屬於 sudo 或 wheel 群組的用戶預設擁有此權限。

**優點 (Advantage)**

- 安全性高：
  - 用戶只使用自己的密碼，root 密碼保持機密。
  - 用戶只在執行單個指令時獲得提升的權限，降低了意外破壞的風險。
  - 可以停用 root 帳號的直接登入，大幅減少暴力攻擊的目標。
- 細緻控制：管理員可以精確地控制每個用戶可以執行哪些特定的指令，實現最小權限原則。
- 完整記錄：所有通過 sudo 執行的操作都會被記錄（通常在 /var/log/auth.log 或類似檔案中），具有良好可追蹤性。

**缺點 (Disadvantage)**

- 設定複雜：正確配置 /etc/sudoers 檔案以實現精細授權相對複雜（儘管對於基本使用來說很簡單）。
- 權限限制：如果沒有在 sudoers 檔案中獲得授權，用戶就不能執行所需的指令。

---

|      | 使用時機                                                       | 理由                                                                                                |
| ---- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| su   | 極少數情況，需要進行一系列連貫、密集且多個指令的 root 任務時。 | 需長時間 root 環境，且是系統的唯一管理員或信任的資深管理員，並知道如何謹慎操作。 （不建議日常使用） |
| sudo | 日常管理，需要以 root 身份執行單一或一組指令時。               | 更安全，有記錄，不需要共用 root 密碼。這是現代 Linux 發行版推薦和標準的管理方式。                   |
