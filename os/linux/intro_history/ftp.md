# ftp

## history

FTP 協定的發展可以追溯到網際網路的前身 ARPANET 時代，其演進大致可分為三個階段：

早期階段：誕生與不安全 (1970 - 1990 年代)

- 誕生：FTP 協定最早的版本於 1971 年由 Abhay Bhushan 撰寫，目的是在主機之間傳輸檔案。它定義了控制通道（Port 21）和資料通道（通常為 Port 20）的雙通道架構，至今仍是 FTP 的核心。
- 普及：隨著 TCP/IP 協定的廣泛應用，FTP 成為最主要的檔案傳輸方式之一。匿名 FTP 的出現，讓使用者無需帳號密碼即可存取公開檔案，極大地推動了網際網路的資訊共享。
- 問題：此階段的 FTP 協定存在一個致命缺陷：所有資料（包括帳號、密碼和檔案內容）都是以明文傳輸，毫無安全性可言。

中期階段：安全化與功能增強 (2000 年代)

隨著網際網路商業化，安全性成為首要考量。

- FTPS (FTP over SSL/TLS)：這是為了解決 FTP 安全問題而產生的協定。它在標準 FTP 的基礎上增加了 SSL/TLS 加密層，確保資料傳輸的安全性。
- SFTP (SSH File Transfer Protocol)：SFTP 不是 FTP 的延伸，而是基於 SSH 協定的獨立子協定。它只需要一個單一的加密通道（Port 22），所有資料傳輸都是安全的。由於其簡單、高效和安全，逐漸成為許多應用程式的首選。

現代階段：專業化與邊緣化 (2010 年至今)

- 雲端儲存衝擊：隨著 Dropbox、Google Drive 等雲端儲存服務的普及，以及物件儲存技術（如 AWS S3）的成熟，FTP 在大眾市場的使用率顯著下降。
- 專業領域應用：儘管如此，FTP 在特定場景下依然不可或缺，例如：
  - 網站管理員上傳和同步網站文件。
  - 大型檔案的分發（如軟體更新）。
  - 在企業內部網路中進行自動化的檔案傳輸。

## software

- Linux/Unix 平台

  - wu-ftpd：作為早期最著名的 FTP 伺服器之一，它曾經廣泛應用於各種 Unix 系統。但由於歷史較為悠久，後續因安全漏洞頻發，逐漸被更現代的軟體取代。
  - vsftpd：全名為 "Very Secure FTP Daemon"，是目前 Linux 系統中最主流的 FTP 伺服器。它的設計理念就是輕量級和高安全性，因此配置簡單、資源消耗低。許多主流發行版（如 Ubuntu、CentOS）都將其作為預設選項。
  - ProFTPD：這款軟體以其高度模組化和類似 Apache 的配置格式而聞名。它功能非常豐富，適合需要精細權限控制、虛擬主機等複雜設定的環境。
  - Pure-FTPd：與 vsftpd 類似，Pure-FTPd 也是一個輕量級、注重安全的 FTP 伺服器。它提供了許多現代功能，如 FTPS、虛擬使用者等，但其程式碼更小、更緊湊。

2. Windows 平台

   - Microsoft IIS FTP Server：FTP 服務是微軟 IIS 的一個角色功能。它與 Windows Server 系統深度整合，提供完整的 GUI 管理介面，適合在企業環境中與其他微軟服務（如 Active Directory）配合使用。
   - FileZilla Server：這是一款廣受歡迎的開源 FTP 伺服器，專為 Windows 設計。它易於安裝和配置，提供了直觀的圖形化介面，支援 FTPS，是許多個人使用者或小型企業的首選。

## concept

FTP (File Transfer Protocol) 的獨特之處在於，它需要兩個獨立的連接埠來傳輸檔案，而不像 HTTP 或 SMTP 那樣只用一個。這兩個連接埠分別是：

- 控制連接埠 (Control Port)：用來傳送命令和接收回應，預設為 Port 21。
- 資料連接埠 (Data Port)：用來傳送實際的檔案資料。

FTP 的兩種模式——主動模式 (Active Mode) 和 被動模式 (Passive Mode)——正是為了處理這個資料連接埠的建立方式。

1. 主動模式 (Active Mode)

主動模式是 FTP 協定最初的設計方式，其核心是「伺服器主動連線到客戶端」。

- 運作流程：
  - 控制連線：客戶端使用一個隨機的高號碼埠，向伺服器的 Port 21 建立控制連線。
  - 發送命令：客戶端透過控制連線發送 PORT 命令，告訴伺服器「請連線到我這邊的一個隨機埠 (例如：12345) 來傳輸資料」。
  - 建立資料連線：伺服器收到命令後，會從自己的 Port 20 主動向客戶端的 Port 12345 建立資料連線。
- 缺點：
  由於防火牆通常會阻擋來自外部網路的「主動」連線，因此客戶端的防火牆很可能會擋下伺服器發起的資料連線，導致檔案傳輸失敗。這使得主動模式在有防火牆保護的客戶端環境中幾乎無法使用。

2. 被動模式 (Passive Mode)

被動模式是為了解決主動模式的防火牆問題而設計的，其核心是「客戶端主動連線到伺服器」。

- 運作流程：
  - 控制連線：與主動模式一樣，客戶端使用一個隨機的高號碼埠，向伺服器的 Port 21 建立控制連線。
  - 發送命令：客戶端發送 PASV 命令，告訴伺服器「我想要進入被動模式」。
  - 伺服器回應：伺服器收到 PASV 命令後，會開啟一個隨機的高號碼埠（例如：54321），並將這個埠號回傳給客戶端。
  - 建立資料連線：客戶端收到埠號後，會從自己的另一個隨機埠，主動向伺服器的 Port 54321 建立資料連線。
- 優點：
  由於所有的連線發起方都是客戶端，而大多數防火牆都允許內網發起的連線，因此被動模式能夠有效地穿越客戶端的防火牆。這使得被動模式成為目前最常用、最推薦的 FTP 連線模式。

| 特性           | 主動模式 (Active Mode)     | 被動模式 (Passive Mode)                             |
| -------------- | -------------------------- | --------------------------------------------------- |
| 資料連線發起方 | 伺服器                     | 客戶端                                              |
| 伺服器埠號     | 控制：21，資料：20         | 控制：21，資料：隨機埠（例如 40000-40010）          |
| 客戶端埠號     | 兩個隨機埠                 | 兩個隨機埠                                          |
| 防火牆相容性   | 差 (客戶端防火牆會阻擋)    | 好 (客戶端連線由內部發起)                           |
| 適用場景       | 在沒有防火牆的內部網路環境 | 大多數情況下，特別是當客戶端位於防火牆或 NAT 後方時 |
